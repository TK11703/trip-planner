# Entry Page Route Contracts

These are browser/UI routes, not new HTTP API endpoints. Route placeholders are GUID-constrained Blazor parameters. Every route uses authenticated Interactive Server pages and reconstructs its state from the URL plus authorized API reads. All entry links are ordinary anchors; mutations remain explicit actions, never GET effects.

IDs identify persisted records, not list offsets; labels are read from authorized data, not supplied in query strings.

## Query contract and origin restoration

| Parameter | Applies to | Validation / semantics |
|---|---|---|
| `returnUrl` | All entry routes | One percent-encoded app-root-relative read-only destination; validate before using it. Generated by a central URL helper from the current parent URI. |
| `legId` | Item create only | Optional GUID belonging to the routed trip and accepting items under `TripLegEligibility`. Invalid/inaccessible/ineligible hints show a recoverable message and never silently assign another leg. |
| `startLocal` | Item create only | Optional ISO local datetime without zone (`yyyy-MM-ddTHH:mm:ss`), matching existing timeline slot or active-day default. Validate through existing temporal rules; do not invent UTC conversion or bypass bounds. Absent: existing form defaults. |
| `view` | Read-only `/trips/{tripId}` return destination | `table` or `timeline`, default table. Add binding in TripDetails; preserve view when generating entry links. |
| `date` | Read-only trip return destination | ISO `yyyy-MM-dd`, within trip dates; selects/restores timeline active date. Invalid values use trip-start/current existing default without throwing. |
| `page`, `pageSize` | Read-only `/trips` origin | Supported positive pagination values subject to existing list limits; bind/restore the originating state. |
| `q` | Read-only `/favorites` origin | Bounded search text using existing search semantics; encode via query helpers, restore on return. |

Query parameters are presentation hints, not authorization claims. Only create pages apply initial-value hints, once after successful load. Edit pages ignore create-only hints and use persisted values. Default controls/new-trip fields continue using the existing forms' behavior. Page URLs must not contain notes, addresses, file contents, credentials, or unsaved form values.

### Return URL normalization

Accept only `/`, `/trips`, `/trips/{guid}`, `/favorites`, and `/inbox/drafts`, with only their permitted origin-state parameters above. Home is accepted because it exposes trip-creation entry points. Fragments are permitted only on trip detail for stable `leg-{guid}` / `item-{guid}` anchors belonging to that trip or the static `unassigned-items` anchor; omit invalid fragments. Enforce bounded length (2048 characters for the normalized return destination), one returnUrl value, and invariant GUID/date parsing. No nested returnUrl or entry-form path may be a destination.

Parse once using a URL/query parser, reject malformed percent encodings/control characters, and validate normalized path/query/fragment rather than doing a raw StartsWith check. Reject absolute URLs even when same-origin, `//host`, backslashes, encoded path separators/bypass strings, any scheme/host/user-info, unsupported queries, and multiple returnUrl values; choose the route's safe default on rejection. Reconstruct accepted destinations from known route identities and encoded allowlisted state. Never repeatedly URL-decode until a string appears valid.

Example of an anchor destination (attribute encoded as appropriate when rendered):

`/trips/{tripId}/items/new?legId={legId}&startLocal=2026-11-02T09%3A00%3A00&returnUrl=%2Ftrips%2F{tripId}%3Fview%3Dtimeline%26date%3D2026-11-02`

Copy this URL into another authenticated tab: it loads the trip, verifies the leg, initializes the same time, displays the full hierarchy, and returns that tab to the same trip/date after Save/Cancel. No originating component instance is needed.

## Page lifecycle, permission and interaction contract

1. Authentication uses the existing `AuthorizeRouteView`; child loading respects `ApiComponentBase` reauthentication. Record-ownership checks apply on cold load and again through server mutation validation.
2. Route/query changes load from IDs in `OnParametersSetAsync` (or equivalent parameter-aware loader) with cancellation/late-response protection. Never reinitialize edited values on a normal render.
3. Entry shell presents title, full trail, parent context and form-specific Save/Cancel. Preserve import's staged action labels and sharing's immediate per-person Share/Save/Remove plus Back/Cancel; explicitly state that applied changes are not undone on exit.
4. Inline field validation, summary and non-field failure messages preserve user input. Do not navigate or mark clean on failure. Guard all mutations before await, disable conflicting actions, and never retry an ambiguous create automatically.
5. Dirty Cancel, breadcrumb, internal links and browser Back ask confirmation. Rejecting stays on the form with values; accepting returns normally. After save, clear the guard before navigation. Browser-native reload/close warning is subject to platform limits in research.md.
6. A link opened in a new tab gets its own form state. Opening the link itself does not discard the current page's state. No programmatic popup or click-preventing handler is required. Optional explicit new-tab links would use `rel="noopener"`, but are not the default design.
7. 360px layout has no horizontal scrolling; controls/actions remain reachable with keyboard open; touch targets are at least 44px. Focus moves to h1 on route navigation using the existing router; validation failures guide focus to an error summary/invalid control.
8. Delete confirmations, trip/favorite maps and reconnect notices remain overlays. Map-to-edit actions that launch an entry page must also expose a genuine edit href, rather than retaining an edit modal.

## Contract acceptance cases

- Every route cold-loads and reloads after navigating from a copied href; all listed actions work on both mobile and desktop.
- Anchor DOM includes usable hrefs for toolbar, table, timeline, empty-state, draft and breadcrumb entry links; modifier/middle-click or context-menu opens the same URL in a new tab.
- ReturnUrl restores allowed search/pagination/view/date, never goes off-site, never returns to another edit form and never relies on a tab's history.
- Viewer cannot load or submit edits; collaborator can edit content but not share; cross-trip leg/item, inaccessible favorite/job/draft and deleted records cannot expose editable state.
- Draft outcome switching, optional leg placement, recognition, import review/duplicate confirmation and share invitations retain existing capabilities.
- Save double-tap yields one in-flight mutation per page; rejected saves preserve input; Cancel/Back do not save local edits.
