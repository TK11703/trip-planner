# Data Model: Trip Data Chat

## Existing Canonical Entities

The following entities remain authoritative and retain their current ownership, sharing, CRUD, and Dapper mappings. Chat does not create a second copy of these records.

| Entity | Current role | Chat use |
|---|---|---|
| `trips` | Trip metadata, owner, dates, description | Search source and citation parent. |
| `trip_legs` | Dated transport/stay/activity legs belonging to a trip | Search source and optional leg citation. Read using the trip owner's ID after access is established. |
| `tracked_items` | Events, reservations, and activities belonging to a trip and optionally a leg | Search source and optional item citation. Read using the trip owner's ID after access is established. |
| `trip_shares` | Viewer/collaborator grants by user ID and optionally email | Existing read-access relationship; consulted fresh for every chat turn. |

Existing `ITripAccessResolver` semantics are authoritative: owners, collaborators, and viewers can read; only existing mutation workflows can write. A trip is accessible by owner user ID, shared member user ID, or a matching invited email. The retrieval SQL must implement the same semantics before similarity ranking.

## New Persisted Search Metadata

### `trip_search_documents`

One row per searchable source entity (trip, leg, or tracked item). This is a rebuildable index, not the source of truth.

| Field | Type/constraint | Purpose |
|---|---|---|
| `search_document_id` | `uuid` primary key | Internal index row identifier. |
| `trip_id` | `uuid` foreign key to `trips`, cascade on trip deletion | Parent used for authorization and cleanup. |
| `owner_user_id` | `text`, indexed | Owner ID needed by existing owner-scoped reads; must match canonical trip ownership. |
| `source_kind` | `text`, constrained to `trip`, `leg`, `tracked_item` | Identifies the canonical source table. |
| `source_id` | `uuid` | Stable ID of the source record. Pair with `source_kind`; not a substitute for canonical lookup. |
| `content_hash` | `text` | Detects source changes and supports idempotent re-embedding. Hash input is not logged. |
| `source_updated_at_utc` | `timestamptz` | Source version used to find missing/stale embeddings. |
| `embedding` | pgvector `vector` | Search vector generated by the configured Foundry embedding deployment. Dimension must match the configured deployment. |
| `embedding_model` | `text` | Exact embedding model/deployment identifier for rebuild compatibility. |
| `embedded_at_utc` | `timestamptz` | Operational freshness metadata. |

Add a uniqueness constraint on `(trip_id, source_kind, source_id)`, indexes supporting trip/source lookup and stale-row reconciliation, and a vector similarity index only when representative measurements justify it. The initial retrieval can use exact cosine-distance ranking. The vector dimension is configuration-bound and validated by the indexer; changing embedding model/dimensions requires re-embedding before querying the new space.

The sidecar stores no duplicate source text. After ranking, authorized source IDs are loaded from the existing tables to produce current prompt context and display labels. A reconciliation pass removes orphaned leg/item index rows. Trip deletion cascades index cleanup.

### Searchable source projection

- Trip: user-visible name, description, dates.
- Leg: title, kind, transportation mode, origin/destination, dates/times, notes, and other non-secret fields already visible in trip details.
- Tracked item: item type, title, location, dates/times, notes, and estimated cost where present.
- Exclude confirmation codes by default. Do not index audit events, authentication claims, sharee directory details, email inbox content, or parsed email bodies.
- Content is normalized for embedding without changing or updating the canonical record. Current canonical field values, rather than stale index text, are supplied to the agent after retrieval.

## Session-Scoped Conversation State (Not Persisted)

### Chat session

An opaque epoch is issued in the authenticated Web cookie at sign-in and rotated for a new sign-in. The Web client uses it only to namespace session storage; it is not a user ID or API authorization claim. The transcript and drawer state live only in browser `sessionStorage` for that epoch/tab. Sign-out, auth expiry, or epoch mismatch clears/discards the prior transcript. No messages, assistant thread IDs, or conversation records are written to PostgreSQL or durable Foundry thread storage.

| State | Fields | Lifecycle |
|---|---|---|
| Session namespace | opaque authentication-session epoch, generated conversation ID, open/closed state | Same-tab route navigation restores state. Discarded on logout/auth expiry/new epoch/tab close. |
| Chat message | role, text, local sequence/order, optional typed citations for assistant display | Bounded client-side transcript; not sent to telemetry. Prior user turns may be sent for follow-up interpretation; old assistant answers are display-only and are not passed back as grounding evidence. |

The session epoch does not grant access. Every request uses the existing authenticated bearer token, and the API independently resolves current trip access.

## Retrieval and Citation Invariants

1. Compute the caller identity from validated authentication; never accept an owner ID, email, access level, or authorized trip set from the request body.
2. Construct the accessible trips set from current ownership and `trip_shares` relationships before vector ranking.
3. Fetch current canonical rows only for authorized candidate IDs; exclude any source no longer accessible or deleted.
4. Each citation is a stable `(trip_id, source_kind, source_id)` reference with display labels from the authorized current row. The model cannot supply a URL, arbitrary trip ID, source label, or access decision.
5. The client generates an internal `/trips/{tripId}` link and may focus a leg/item only through a validated stable source ID. The existing destination route independently enforces access.
6. The agent has no write tools. Index maintenance may change only `trip_search_documents` and never changes trips, legs, tracked items, or sharing records.
